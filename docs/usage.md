# 操作与参数

![界面](preview/ui.png)

| 操作 | 键 / 按钮 |
| --- | --- |
| 暂停 / 继续 | 空格 或「暂停」 |
| 放一发 | R 或「放一发」；**点/触摸画面**则在那个位置炸一发 |
| 收起 / 显示面板 | Esc 或「收起」（收起后左上角留一个「控制台」按钮把面板叫回来；`?ui=0` 是彻底无 UI，连它也不留） |
| 换种子 | 「随机」（数字，钉住这一场）；「每日」= 今天这一场，**并跟着日期走**（见下） |
| 插播 | 往种子框里敲字母 —— 有一个词，拼全的那一刻会插播参考图风格的两发（当场生效：不进链接/文件名/元数据/浏览器存储） |
| 重放 / 存图 | 「重放」/「存图」 |
| 分享 | 「链接」：把这一场的 `seed`（与非默认的预算）拼到当前页面地址上 |
| 全屏 | 「全屏」（Esc 退出；录制中 Esc 优先停录制） |
| 录制 | 「录制」：录成 WebM，再点一次或按 Esc 停止（录满 30 秒自动停） |
| 画面容量 | 「绘制预算」滑块（80~1500，默认 450） |

在种子框里打字时，空格 / R 让位给输入（那是那个词的输入）；回车、或点一下画面，
就把键盘还给快捷键，Esc 任何时候都有效。
点击发射走 pointer 事件，所以手机触摸同样可用（canvas 已设 `touch-action: none`）。

## 存图与录制：元数据

| 动作 | 产物 | 元数据里写了什么 |
| --- | --- | --- |
| 「存图」 | PNG（文件名带种子） | `Software` · `Seed` · `Comment`（**这一场的链接**）· `Creation Time` |
| 「录制」 | WebM（文件名带种子） | `SEED` |

两边的 `Seed` 都是**数字种子**：那个词不是种子（只在敲对的那一刻当场生效），所以它不会出现在
文件名、元数据或链接里 —— 这三个地方都是会被转发的，彩蛋不能顺着它们传出去。

两边的实现不一样，原因也值得知道：

- **PNG** 是"裸"的（canvas 自己导出时不带任何文本块），所以 `src/pngmeta.js` 直接往字节流里插
  **iTXt** 块（用 iTXt 而不是 tEXt，因为它是 UTF-8，中文不会坏），插在 IHDR 之后 —— 图本身
  一个像素都不动，`IDAT` 也不受影响。
- **WebM** 只能写 `SEED`：MediaRecorder 不给写 tag 的接口，只能覆盖 Chromium 的 muxer 在头部
  留的 **Void 空隙 —— 实测固定 47 字节**（2 秒和 8 秒录制都一样），装得下种子、装不下一个
  46 字符的链接；而 ffmpeg/播放器只在第一个 Cluster 之前找标签，尾接的读不到。链接就放
  PNG 元数据和文件名里。

读出来看看：

```bash
exiftool shot.png                                   # PNG：Seed / Comment …
ffprobe -v error -show_entries format_tags clip.webm # WebM：SEED=…
```

## 录制

- **只录画布**：`canvas.captureStream()` 抓的是 canvas 自己画的东西，面板、HUD、
  底部的录制指示条都是浮在上面的 DOM，天然不在画面里；录制期间自动收起面板只是
  让你看着干净，按 Esc 或点指示条上的「停止」结束。
- 编码交给浏览器（VP9 → VP8 兜底），**没有依赖也没有素材**。
- **种子写进元数据**：MediaRecorder 没有写 tag 的接口，所以录制结束时自己往 WebM
  的 EBML 里写一个 `Tags`（`SEED`）—— 详见 `src/ebml.js` 顶部注释（关键是覆盖
  muxer 在头部留下的 Void 填充块，既在前部又零偏移）。用 `ffprobe` 能看到：
  `"tags": { "encoder": "Chrome", "SEED": "7" }`。
- 文件名也带种子，例如 `fireworks_seed7_2s.webm`。

URL 参数：`?seed=7`、`?frames=90`、`?still=1`、`?ui=0`、`?max=900`、`?w=924&h=691`
（老链接里的 `?scene=…` 会被直接无视，不影响那一场）

* `frames=N` 先走 N 个固定步再定格（第 1 帧 = `step(0)`）；`still=1` 等价于 `frames=1`
* `ui=0` 隐藏全部 UI；`w`/`h` 钉死逻辑坐标系（构图与窗口大小无关，方便截图与复现）
* `seed` 只认数字；那个词写进 `?seed=` 不生效（它不是种子，见上）

## 「每日」是个开关

同一天永远是同一个数字（`src/rng.js` 的 `dailySeed()`：把本地日期串 `2026-9-24` 做 FNV-1a，再
`% 999999 + 1`，只认日期不认时分秒 —— 纯算出来的，不联网也不存任何东西）。但**光算出来还不够**：
还得知道"你现在这一场是不是每日"，否则第二天没法自动换场。

所以「每日」是个开关（按钮亮起 = 打开），状态存在 `localStorage` 的 `fw.daily` 里：

- 第一次来（没 URL 种子、也没存过种子）→ 放今天这一场，开关自动打开
- 开着的时候，**每次打开页面都换成"打开那一刻的今天"** —— 昨天存的种子会被今天的覆盖
- 页面一直开着跨过本地午夜 → 主循环每 500ms 检查一次日期，过了就自己换场（控制台说一句
  「跨日 —— 换成今天的这一场」）；标签页在后台时 rAF 本来就停着，回到前台时补上。
  **暂停中不打扰**，解除暂停后的第一拍才换
- 「随机」、或在种子框里敲一个数字 = 明确选了这一场 → 开关关掉，不再跟日期走
- 链接里带 `?seed=` = 明确要那一场 → 也关掉开关（分享出去的链接永远指向同一场，隔天也不会变）
- 「重放」和新特性插播都不动这个开关

## 它记了什么

浏览器存储（`localStorage`）里只有**两个键**，都是这套种子规则要用的：

| 键 | 内容 |
| --- | --- |
| `fw.seed` | **上次那一场**的数字种子（`URL -> 上次用过的 -> 今天这一场` 这条优先级用） |
| `fw.daily` | `'1'` / `'0'` —— 「每日」这个开关：`'1'` = 这一场跟着日期走 |

没有 cookie、没有网络请求、没有第三方脚本。**那个词从不写进去**（更早的版本存过，现在开机时会
把认不出来的旧值抹掉）；存储被禁用（隐私模式等）时全部读写都包在 `try` 里，最坏只是每次回到
今天那一场。

## 分享与托管

「链接」会把这一场的 `seed`（以及非默认的预算）拼到**当前页面地址**上，
所以托管在子路径下也照样能用。

### 线上地址

| 地址 | 是什么 |
| --- | --- |
| <https://cht-1192.github.io/Fireworks/> | 这个 Demo 的线上版 |
| <https://cht-1192.github.io/> | 入口页：三个纯前端 Demo 的入口（另两个是 2D 光线追踪、网页版示波器） |

发布方式：**本仓库自己的 GitHub Pages**，源是 main 分支的 `/docs` 目录 —— `npm run build`
每次都会把同一份产物同时写进 `dist/` 和 `docs/index.html`（字节一致、可复现），所以线上不会
落后于代码。**更新线上的步骤就是 `npm run build` 之后提交并推送。**

入口页那边只放一张预览图和一张卡片（指向 `/Fireworks/`），它自带的同步脚本会比对线上产物与
本地 `dist/` 的哈希，不一致会提醒一句。
