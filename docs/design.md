# 设计取舍

写给要改这份代码的人：几个"为什么这么写"的决定，以及背后的实测数字。

## 尾迹：为什么是一条描边，而不是一串图章

原版（`reference/turtle_fireworks.py`）的尾迹一节一节的，纯粹是 turtle 的限制：它没有"带粗细的
折线"图元，只能把真实轨迹抽稀成 2~6 段（`trail_seg` 的注释就叫**图章预算**），每段单独盖一个
矩形图章 —— 所以既看得见接头豁口，弯道处又会折成多边形。

canvas 有 `stroke()` + `lineCap/lineJoin = round`，于是一条真实轨迹就是**一整条路径**：沿已经算好
的真实轨迹细采样（火花 14 段、发射尾迹 48 段封顶），连成光滑带子，接头由圆头补齐；每段仍按
原公式取色取宽，"越旧越暗越细"的渐变照旧。

代价：绘图指令变多（每段一次 `stroke`），换来的是没有折线感。实测（预算 1500、无头 CPU 光栅化）
命令录制耗时平均 **0.23 ms / 帧**，p95 0.4 ms —— 60fps 的预算是 16.7 ms，所以这不是瓶颈。

图元只剩两种：**圆点**（正 18 边形，沿用 turtle 那份形状表）和**折线**。原版那个"单位矩形"
（`RAY`）随复刻场景一起删了 —— 折线用两段以上的点就能表达任意线段。

## 绘制预算：容量，不是死线

`Show` 每帧统计**实际绘制开销**（折线按段数、圆点各算 1），默认 450。它是**画面容量**：空着就
多发、每发更大；满了就少发、每发更小 —— 同时作用于"每发多少颗"和"多久放一发"。

实测（默认预算、60 秒）：

| 预算 | 图元均值 | 图元峰值 |
| --- | --- | --- |
| 450（默认） | 68 | 206 |
| 900 | 113 | 286 |
| 1400 | 173 | 567 |

节流是启发式的（只影响**后续**发射的火花数），所以单帧峰值会超过预算，实测约 1.2~2 倍 ——
齐射是瞬时的。HUD 的「预算」一行就是 `上一帧 / 上限`，所以看得出来滑块在起什么作用。

> 历史坑：早先这层节流只会往**下**压（`density()` 最大 1.0），于是把预算调到 1500 也毫无变化
> —— 因为整个秀是发射节奏限流的。改动的来龙去脉见 `npm run baseline` 的说明与 git 历史。

## 固定 1/60 步长：为了"同一个种子就是同一场"

主循环用累加器 + 固定 1/60 步长推进物理，而不是跟着 `requestAnimationFrame` 的实测间隔走。
原版交互模式用实测 `dt`，帧率一抖整场就不同，其实只有它的 `--render` 是确定的。固定步长之后
"同种子 = 同一场"严格成立（单帧最多追 4 步，掉帧不雪崩），也与原版离线渲染的口径一致。

顺带：数字种子走 CPython 的 MT19937 播种，**逐位一致**（`npm run rng` 守着，1072 项）；含字母的
种子走本版自定义的 FNV-1a，不保证跨语言。

## 只有一种秀，"参考图风格"是一次插播

早期有过一个 `original` 场景（按参考截图量出来的坐标/颜色摆那两发）。它连同专用机件（50 行实测
数据、`FixedLine`、`stemSegments`、只被直线辐条用到的 `RAY` 图元）一起删掉了：留着它就得一直维护
一套"只服务于对拍"的脚手架。

后来 `classic` / `random` 两个"场"也删了：两者的差别只是开场那两发照参考图的配色与花型，之后
走的是同一套随机逻辑，为此维护一个 `scene` 概念（`SCENES` 表、`sceneForSeed()`、`?scene=` 参数、
HUD 里的「场景」一栏、PNG 里的 `Scene` 标签、文件名里的场名）并不划算。现在整场秀只有一种
（纯随机），参考图那两发降级成**一次插播**：`Show.interlude()` —— 由那个词触发，敲全的那一刻插进
**正在放的**这一场里。老链接里的 `?scene=` 被直接无视，不影响 seed 指定的那一场。

## 那个词发不出去

彩蛋是给别人自己去碰的，所以凡是**会被转发的东西**都不能带上它：链接、文件名、PNG / WebM 元数据、
控制台输出、屏幕上的种子框。做法不是"写的时候过滤掉"，而是让它**压根不是状态**：

- 那个词**不是种子**。`seed` 只认数字（`seedFromRaw()`），`?seed=<词>` 不生效；敲对时只调用一次
  `App.interlude()` 往正在放的这场里插两发，种子仍是原来那个数字。于是 `shareUrl()`、文件名与
  元数据里自然只有数字，不需要任何"打码"逻辑。
- 插播之后种子框会被刷回那个数字种子（`syncPanel()`），屏幕上不留痕迹。
- 控制台也不打印它：提示只说"有一个 9 个字母的词"，敲对后那行日志只写"插播：参考图风格的两发"。
- 代价是这份观感不可被复现/分享 —— 这正是目的。

**残留的口子**：它是纯前端彩蛋，词就写在 `src/app.js` 的 `SECRET` 里，读了源码的人还是能直接
看到（客户端藏不住东西）；这里做到的是"App 自己不会把它传出去"。

## 可复现的构建与截图

- `npm run build` 的产物**可复现**：不含时间戳，同样的源文件字节完全一致（`--stamp` 才写）。所以
  `dist/` 与 `docs/index.html` 入库不会产生无谓 diff。
- 门面图也是可复现的：`npm run shot -- --url "?seed=7&frames=1&max=1500" --spam 16 --step 200`
  —— 先冻住、真键盘按 16 次 R、再同步推 200 帧。画面逐像素一致，只有 HUD 里的 fps 读数会变。
- 图标没有栅格图：`favicon.svg` 是源文件，`favicon.js` 把它压成 data URI 内联进页面 —— 单文件版
  必须**零外部请求**。

## 元数据：两个容器，两种办法

导出的文件都要能"拿到就复现同一场"，所以种子（以及这一场的链接）写进文件元数据。

- **PNG**（`src/pngmeta.js`，纯函数、Node 可测）：往字节流里插 **iTXt** 块，插在 IHDR 之后。
  用 iTXt 而不是 tEXt 是因为它按 UTF-8 存，中文不会坏；图本身一个像素都不动，`IDAT` 与所有块的
  CRC 都保持正确。crc32 用标准测试向量（`"123456789"` → `0xCBF43926`）守着。
- **WebM**（`src/ebml.js`）：MediaRecorder 不给写 tag 的接口，只能覆盖 Chromium 在头部留的
  **Void 空隙 —— 实测固定 47 字节**（录制多长都一样），装得下 `SEED`、装不下 46 字符的链接；
  而 ffmpeg/播放器只在第一个 Cluster 之前找标签，尾接的读不到。所以 WebM 只写种子，
  链接去 PNG 与文件名里。
